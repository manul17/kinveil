# Security Policy

## Supported Versions

Only the latest release on the `0.1.x` line receives security fixes.

## Security Model & Scope

- **Local vault:** `state.enc` (`KVEL\x01`) is encrypted with Argon2id (`128 MiB`, `t=3`, `p=1`) and AES-256-GCM with header AAD. All private keys, user tokens, server inventory, and `config.toml` remain inside the encrypted vault.
- **Editor isolation:** `kinveil config` decrypts only global non-key settings (`config.toml`) into RAM-backed `/dev/shm` tmpfs (`0700`/`0600`) and zeroes temp files on exit; private keys never open in `$EDITOR`. Child processes spawned for `EDITOR`/`KINVEIL_PASSPHRASE_COMMAND`, `git`, `go`, and `ssh` strip `LD_PRELOAD`, `LD_LIBRARY_PATH`, and `DYLD_INSERT_LIBRARIES`.
- **Verified transport & artifacts:** Deployments verify pinned OpenSSH host public keys (`StrictHostKeyChecking=yes`, `ClearAllForwardings=yes`, `-T`) with `--` argument separation and input validation. Upstream `xray` and its `geoip.dat`/`geosite.dat` assets are verified by release zip and extracted/bundled SHA-256 (`XRAY_BIN_SHA256`, `XRAY_GEOIP_SHA256`, `XRAY_GEOSITE_SHA256`), and `amneziawg-go` is verified against bundled/prebuilt release SHA-256 (`AWG_PREBUILT_SHA256`), a pinned upstream commit build, or a verified SHA-256 `[artifacts]` URL; optional `[artifacts]` TOML overrides (`xray_zip_*`, `geoip_*`, `geosite_*`, `amneziawg_*`) enforce strict HTTPS + SHA-256 pairs and reject local/private destinations, and `KINVEIL_XRAY_BIN` / `KINVEIL_AMNEZIAWG_BIN` verify Linux `x86_64` ELF headers.
- **Server isolation & egress filtering:** Caddy runs with `admin off` over mode `0710` subscription directories. Deployments disable `systemd-resolved` LLMNR/MDNS (opportunistic DoT) and harden `sshd` to key-only authentication on `admin_ssh.port` when `authorized_keys` is populated. Xray runs unprivileged as user `kinveil` with encrypted DoH DNS, `uid-<uid>:<proto>` client tags (no plaintext usernames on VPS disks), and `freedom` outbound `sockopt.domainStrategy: UseIP` (mitigating DNS-rebinding SSRF); all four VPN protocols (Xray, forwarding-only OpenSSH `vpnssh*` in `output`, and AmneziaWG `kv0` in `forward`) are uniformly restricted at the Linux kernel layer via `/etc/kinveil/nft-blocked.nft` (`@egress_blocked_v4`/`@egress_blocked_v6`) and `/etc/kinveil/nft-egress.nft` inside `table inet kinveil`, always rejecting loopback, unspecified, link-local, multicast/reserved, and cloud IMDS (`169.254.0.0/16`, `100.100.100.200/32`, `fd00:ec2::254/128`) destinations alongside any configured country/custom CIDRs regardless of `[firewall] block_private_networks`, while AmneziaWG `kv0` blocks peer-to-peer lateral traffic and clamps TCP MSS. On-server firewall auto-updates (`update-firewall.sh`) enforce HTTPS (`--proto '=https' --tlsv1.2`), strictly validate and canonicalize every CIDR line, fail closed on malformed or empty input, verify syntax with `nft -c`, and atomically reload sets.
- **Opt-in traffic accounting (`--traffic`):** Disabled by default on every server. When opted in per server, Xray's `StatsService` binds strictly to a `0700` UNIX domain socket (`/run/kinveil-xray/api.sock`) and daily UTC rollups in `/var/lib/kinveil/traffic` (`0700`, `0600` files) record only numeric `uid` byte totals and public NIC byte totals—never destination IPs, domains, or usernames—and are pruned after `[traffic].retention_days` and wiped on `--no-traffic`, `disable`, or `remove --wipe`.
- **Redacted diagnostics:** Probe failures and debug output redact secret subscription `base_path`s, tokens, private keys, and API credentials.

## Reporting a Vulnerability

Please report security vulnerabilities privately via GitHub Security Advisories (**Security -> Advisories -> Report a vulnerability**) rather than opening a public issue. Include reproduction steps, affected version, and impact assessment.
